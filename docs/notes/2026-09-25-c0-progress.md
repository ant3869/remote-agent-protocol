## Per-task status

### Preset verification (before Task 1): **done, two corrections found**

Checked every preset base URL and models/key-info path against each provider's current docs
(web fetch/search), not the spec draft's numbers. Two were wrong and got corrected:

- **DeepSeek**: spec draft said `https://api.deepseek.com/v1`; current docs use
  `https://api.deepseek.com` (no `/v1`).
- **Together**: spec draft said `https://api.together.xyz/v1`; current docs use the `.ai` domain,
  `https://api.together.ai/v1`.

Everything else (OpenRouter, 9Router per Ant's own instruction, OpenAI, Anthropic, Gemini, xAI,
Groq, Mistral, Ollama, LM Studio) matched the draft. Full source-by-source table is in the plan file.

### Task 1 -- `secret_store.py`: **done**

Windows Credential Manager (`win32cred`) generic credentials, target `RAP/model-provider/<id>`,
matching the pattern the widely-used `keyring` package uses for its own Windows backend (verified
against `keyring`'s real source, not guessed). No plaintext fallback: if Credential Manager is
unavailable, `set_key` raises `SecretBackendUnavailable` rather than falling back to memory or disk.
`install_log_redaction()` scrubs any key this module has ever handed out from loguru's output.

A security review (via the `security-reviewer` subagent) of this module before it went further found
one real HIGH-severity gap: only `set_key()` tracked values for redaction, so a key loaded from
Credential Manager on every *later* app start (the dominant real usage path -- you save a key once,
then every subsequent start just reads it back) was never covered. Fixed in `e59c3f5be`, with a
regression test.

### Task 2 -- `model_providers.py` registry: **done**

`ProviderRegistry` persists to `data/model_providers.json`, schema-versioned and atomically written
(temp-file + `os.replace`), mirroring the pattern `conversation_hub/store.py` already uses. Holds no
secrets: `ProviderConfig` structurally has no key-shaped field, and loading a payload drops any stray
`api_key`/`token`/etc. rather than trusting it. Also holds the preset table, cached model catalogs,
cached test results (per provider and per model), and each role's ordered fallback chain.

### Task 3 -- `llm_endpoint.py` role-chain resolution + `NARRATION`: **done**

Resolution order per role: an assigned role chain wins outright; an empty one falls back to exactly
today's `CLOUD_*`/`OPENROUTER_API_KEY` env behavior, unchanged. Added `NARRATION` as a fourth caller --
it has no legacy env path of its own (a role chain is the only way to put narration in the cloud), so
existing installs never start narrating in the cloud just because this shipped. `Endpoint.provider_id`/
`extra_headers` were added; the API key for a role-chain endpoint is fetched from `secret_store` at
call time and is never cached on the frozen dataclass.

`narration.py` now resolves through the narration role assignment when one exists (OpenAI-compatible
`/chat/completions`, via the assigned provider), but an explicit `host=`/`model=` constructor override
(as the existing "dead Ollama" test uses) still bypasses role resolution entirely and keeps today's
native Ollama `/api/chat` behavior byte-for-byte.

All 11 pre-existing `test_llm_endpoint.py` tests and all 13 pre-existing `test_narration.py` tests
pass unmodified -- the parity guarantee for "existing behavior unchanged when nothing is assigned."

### Task 4 -- `provider_tests.py` staged pipeline: **done**

Two pipelines, each stage gated on the one before it and bounded by its own timeout: a provider test
(reach -> authenticate -> catalog) and a model test (chat -> tool call -> JSON mode). Exercised against
a real local fake OpenAI-compatible HTTP server (`tests/fake_openai_server.py`, flat in `tests/` to
match this repo's actual convention -- the plan named a `tests/fixtures/` path that doesn't exist here)
rather than mocking `aiohttp`, so the HTTP round-trips are real.

Every public entry point (`run_provider_test`, `run_model_test`, `refresh_catalog`) redacts every
stage's `detail`/`hint` through `secret_store` before returning, closing a gap where only HTTP error
bodies were explicitly redacted and an exception's own message (`str(exc)`) was not -- covered by a
dedicated test that monkeypatches a connection failure to raise an exception embedding a live key.

### Task 5 -- Web API actions: **done**

`provider_save` / `provider_delete` (refused while a role chain references the provider, unless
`force`) / `provider_test` / `provider_refresh_models` / `model_test` / `role_assign` / `import_env`,
all through the existing CSRF'd `/api/action` dispatcher, plus a read-only `GET /api/providers`. Test
pipelines run on a background thread and publish their result over the existing event stream
(`provider_test_result` / `model_test_result` / `model_assignment`) rather than blocking the request.

The key never appears in `/api/providers` (structurally -- there is no key field to spread), `/api/status`,
or the diagnostics export (neither of the latter two ever touch the registry or secret_store at all).

### Task 6 -- Settings UI: **done, with two deferrals**

New "Models & providers" settings section, between General and Voice as the spec asked: provider
cards (Test / Refresh models / Edit / Delete, masked key, last-test dot, model count), an add/edit
form, a searchable model browser (cached catalog + manual model-ID entry, Test button per row, badges
once tested), and a role-assignment editor (add/remove chain entries) for all four roles. Command
palette gained "Open models & providers" and "Test providers".

Deferred, tracked in the plan file's Deviations section rather than silently dropped:
- **Chain reordering** -- add/remove work; there's no drag-or-arrow reorder control. Multi-hop chains
  are the less common case (most roles get one provider+model), so this was judged lower value than
  the rest of the UI given the remaining scope.
- **Status view** -- the spec asked for the existing "Persona orchestration" panel to show which
  provider/model actually answered each role's last turn. Not wired up; that panel belongs to a
  different, pre-existing feature and doing this properly was out of scope for this pass. The
  provider/model test badges in the new panel are the substitute for now.

Two real bugs were found and fixed while building this (not just cosmetic): `/api/providers`'s catalog
summary only exposed a model *count*, not the actual model-ID list the browser needs to render rows
(`_catalog_summary` now includes `models`); and `provider_save`'s "auto-test a newly created provider"
step used a fragile "assume it's last in the list" heuristic instead of the id the server actually
resolved (now returned explicitly as `result.id`).

### Task 7 -- `.env` import migration: **done**

`model_providers.env_import_available()` / `import_from_env()`: a one-time offer, shown only while the
registry has never held a provider. Creates one provider from `CLOUD_LLM_BASE_URL` (preset detected as
`openrouter` when the URL matches exactly, else `custom`), copies `CLOUD_LLM_MODEL` /
`CLOUD_INTENT_MODEL` / `CLOUD_ORCHESTRATION_MODEL` into the butler/intent/orchestration role chains
(falling back to the shared brain model per role, same as today's legacy resolution), and returns the
key for the caller to store via `secret_store` -- this module never touches `secret_store` or `.env`
itself. `.env` is never written; the UI banner tells Ant what he can remove once he's happy with it.

One real bug found while wiring the UI action: `import_env` was implemented and tested at the
`model_providers` level but never actually registered in `web_gui.py`'s `_actions` dispatch dict, so
the button would have failed with "unknown action" -- caught by an integration test that calls the
action end-to-end (not just the underlying function), fixed before commit.

### Task 8 -- Docs + CHANGELOG: **done**

`CHANGELOG.md` `[Unreleased]` gained a feature entry. `docs/architecture.md`'s existing "Model
endpoints (local and cloud)" section was extended (four callers now, not three) and gained a new
"Model providers and role assignment (Phase C0)" subsection describing the registry, secret store,
test pipeline, and web/UI surface.

## Deviations from the spec (full detail in the plan file)

1. Two preset base URLs corrected against current docs (DeepSeek, Together) -- see above.
2. Test fixture lives at `tests/fake_openai_server.py`, not `tests/fixtures/fake_openai_server.py`
   (matches this repo's actual flat convention for shared test helpers).
3. Added `cfg.MODEL_PROVIDERS_PATH` + a `tests/conftest.py` sandbox entry (mirroring the existing
   `CONVERSATION_STORE_PATH` pattern) so `llm_endpoint`'s registry singleton never touches real app
   data during a test run -- not asked for explicitly, but the same problem that pattern already
   exists to solve.
4. `/api/providers`'s wire format uses snake_case for provider/role/test-result fields (matching the
   on-disk JSON schema) instead of remapping to camelCase like the rest of `/api/status`. Functional,
   but a real inconsistency with this app's usual convention -- worth a follow-up cleanup, not blocking.
5. Settings UI: no chain-reorder control, and the existing "Persona orchestration" status panel was not
   wired to show live role-assignment results (see Task 6 above).

## What Ant must do to try it

1. Launch the app (`python -m remote_agent_protocol`), open the control-center UI, go to
   **Settings -> Models & providers** (new nav button, between General and Voice).
2. **To add OpenRouter:** pick "OpenRouter" from the preset dropdown (base URL prefills to
   `https://openrouter.ai/api/v1`), give it a label, paste an OpenRouter API key, and press
   **Save & test**. It reaches, authenticates, and lists the catalog; watch the provider card's status
   dot and the model count.
3. **To add 9Router:** pick "9Router" (base URL prefills to `http://localhost:20128/v1`), paste the
   key from the 9Router dashboard (`http://localhost:20128/dashboard`), and **Save & test**. If
   9Router isn't running, the reach stage says so plainly.
4. **To assign a role:** in the model browser, pick the provider, search or scroll its cached model
   list (or type a model ID manually), press **Test** on the one you want, then use the role
   assignment section's chain editor (Butler / Intent / Orchestration / Narration) to add that
   provider+model. It applies on the next turn -- no restart needed.
5. If `CLOUD_LLM_BASE_URL` or `OPENROUTER_API_KEY` is already set in `.env`, a one-time **Import from
   .env** banner appears at the top of the panel the first time this section is opened (before any
   provider is configured); it moves that config into the new registry without touching `.env` itself.
